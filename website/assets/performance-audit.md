# Проверка загрузки Fiery Led Lamp и Web Flasher

Проверка выполнена по исходникам основного сайта, Web Flasher, PHP API, статистики, общего шаблона, SQL-миграций и workflow публикации. Зафиксированная исходная версия: `55ca9f5f208cb7c4ccd0714dce94e0bd1b8a78c5`. Прямые замеры времени ответа production-хостинга из этой среды недоступны; приведённые ниже величины — размеры исходных ресурсов и результаты локальной функциональной проверки, а не обещание времени загрузки в секундах.

## Найдено и исправлено

1. Web Flasher загружал JSZip с jsDelivr обычным блокирующим `<script>`, а его модуль приложения зависел от загрузки esptool-js с unpkg. Сбой или медленный ответ любого CDN задерживал готовность интерфейса. Обе библиотеки тех же версий теперь находятся на своём сайте и загружаются только при начале прошивки. Архив `update.zip` по-прежнему скачивается только после действия пользователя. Запрос COM-порта остаётся перед асинхронной загрузкой библиотек, чтобы сохранить активацию пользователя.
2. Статистика могла ждать определения страны до трёх секунд. Основной PHP API при этом удерживал сессию пользователя, блокируя параллельный запрос `me` из шапки. Публичные события, скачивания и изображения теперь не открывают сессию. Просмотр страницы регистрируется после загрузки, в свободное время браузера; быстрый уход со страницы обрабатывается через `pagehide`. На странице прошивки статистика больше не использует объект `Image`, участвующий в загрузке страницы.
3. Гостевой запрос `me` подключался к базе и проверял её схему, хотя пользователь ещё не вошёл. Теперь ответ 401 формируется до подключения к БД. Содержимое авторизованного аккаунта и CSRF-токен по-прежнему проверяются сервером.
4. Шапка, кабинет и форум повторно запрашивали один и тот же аккаунт. Теперь они разделяют один ответ в пределах открытой страницы, получая отдельные `Response.clone()`. Изменение настроек, имени, пароля и аватара сбрасывает ответ. Данные аккаунта не сохраняются в браузерном хранилище.
5. Проверка колонок аккаунта выполнялась при каждом запросе; форум повторял `CREATE TABLE` и попытки `ALTER TABLE` при чтении сообщений и файлов. После успешной проверки создаются маркеры схемы в существующей приватной папке сервера. Ключ учитывает версию миграции, DSN и пользователя БД. При невозможности записи сохраняется прежняя проверка; при неполной схеме маркер форума не создаётся.
6. Общий `site.js` содержал код кабинета, администрирования и истории версий для всех страниц. Он разделён: общий файл содержит статистику и прокрутку вверх, а `scripts/account.js`, `admin-stats.js`, `admin-users.js`, `instruction.js` и `versions.js` подключаются на соответствующих страницах с `defer`.
7. Удалены 80 правил старой шапки из `styles.css` и 54 из `firmware/style.css`. Селекторы `.site-header`, `.nav-wrap`, `.nav`, `.menu-btn` не используются текущими страницами. Оформление тела страниц и новый общий компонент сохранены.
8. Одинаковый `site.js` имел разные query string на кабинете, форуме и страницах входа, создавая разные ключи кеша. Сборщик теперь задаёт один хеш содержимого для каждого CSS/JS на всех страницах. История версий использует HTTP-перепроверку `Version.txt`, а не новый URL с `Date.now()` при каждом посещении.
9. Поиск больше не скачивает индекс размером около 99 КБ при простом фокусе пустого поля: загрузка начинается при реальном запросе.
10. Схема подключения в PNG занимает 2 296 595 байт. Новый этап публикации создаёт lossless WebP, проверяет точное совпадение RGBA-пикселей и использует WebP только если он меньше. Исходный PNG остаётся доступен по прежней ссылке. Добавляются размеры изображения и асинхронное декодирование. Точный результат для production PNG выводится в шаге `Optimize connection diagram` workflow.

## Размеры

Байты до HTTP-сжатия, первый визит с пустым кешем. В наборы страниц входят HTML, подключаемые CSS/JS и начальные зависимости модулей; данные API, иконка браузера и изображения вне этих наборов не учитываются.

| Набор | До | После | Сокращение |
| --- | ---: | ---: | ---: |
| Общий `site.js` | 39 384 | 2 425 | 93,8% |
| Основные стили | 108 959 | 94 603 | 13,2% |
| Стили Web Flasher | 36 262 | 27 248 | 24,9% |
| Главная: HTML + CSS + JS | 192 592 | 141 613 | 26,5% |
| Web Flasher: HTML + CSS + JS | 415 814 | 91 726 | 77,9% |

Библиотеки общим размером 316 181 байт не исчезли из проекта: они перенесены из начальной загрузки на момент прошивки. На уже открытой странице они загружаются один раз.

## Что не влияет на первоначальную загрузку

Старые PNG-значки и внешний SVG-спрайт не запрашиваются новой шапкой. EXE, IPA, BIN и `update.zip` не скачиваются браузером просто из-за своего наличия на сервере. `worker.js`, `website/src/index.js` и перенаправление старой страницы обсуждений относятся к прежней структуре и не входят в текущую начальную загрузку HostiMan. Удаление таких файлов само по себе не ускорило бы открытие страницы.

## Проверки

- Синтаксис JavaScript и PHP; повторная сборка общего компонента без изменений.
- PHP 8.3: гостевой `me` с недоступной БД, авторизованный `me`, отклонение неверного CSRF, скачивание с перенаправлением, отсутствие сессионных cookie у публичных запросов, отсутствие повторных SQL-миграций между запросами.
- Браузер: единый запрос аккаунта у шапки и кабинета на локальных тестовых данных; отложенная загрузка поиска; фильтрация инструкции и 77 версий; готовность конфигурации Web Flasher до загрузки библиотек.
- Загрузка локальных esptool-js 0.6.1 и JSZip 3.10.1 по требованию, проверка экспортов и ZIP с CRC32. Запись в физическую ESP32-S3 требует отдельной проверки с платой; алгоритм записи не менялся.
- Генератор WebP на тестовом PNG: пиксели совпадают, ссылка скачивания PNG сохранена, повторный запуск не изменяет результат.

## Что ещё проверить на HostiMan

Нужны реальные TTFB, ответы DNS/TLS и HTTP-заголовки обоих доменов. Если задерживается сам HTML до начала загрузки ресурсов, это отдельная задача хостинга. В конфигурации nginx стоит проверить сжатие статических HTML/CSS/JS/SVG и политику кеша: длительный кеш для ресурсов с версией содержимого, перепроверка для HTML и `Version.txt`, сохранение `no-store` для аккаунта и действий API. Эти настройки сервера в репозитории отсутствуют и этой правкой не менялись.

Официальные справочники: [nginx gzip](https://nginx.org/en/docs/http/ngx_http_gzip_module.html), [nginx Cache-Control/Expires](https://nginx.org/en/docs/http/ngx_http_headers_module.html).
